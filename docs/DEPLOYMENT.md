# 部署与运行边界

## 演示与真实模式

演示：使用 README 的 Compose，只有虚构账户和图形，不连接平台。真实模式：复制仓库到独立目录，创建新卷和空数据库，先运行 setup，再在私有 `.env.local` 设置 `DEMO_MODE=false`，提供自己的只读平台授权。应用不会自动清除旧演示记录；不要复用演示库。

应用数据库名为 `meta_ads_workbench`，应用角色为 `aepi13_zaku_app`。默认 Compose 为方便演示将初始化所有者同时用作应用角色；**生产应由管理员初始化 schema 后，改用非超级用户、限制在此库的角色**。不要直接把演示 Compose 当作生产加固模板。

## Meta

运行 `npm run vendor:meta` 下载官方开源仓库的固定提交并构建（会执行该依赖的 npm 安装/构建脚本）。检查其来源及许可证后再运行。需要自己的 `META_ACCESS_TOKEN`，只授予必要的读取权限。容器中的 vendor 目录为只读挂载。代理仅使用自己批准的代理，凭据进入私有环境配置。

首次进入真实模式先发现账户，再同步一个小日期区间，核对账户原生总计、时区、币种及7天点击/1天浏览口径。未返回的数据保持缺失。不要直接用全历史的大查询证明“已抓全”。

## Google

适配器不是内置即用功能。需自行安装官方 google-ads-mcp、配置 OAuth、开发者令牌和可访问账户，并在环境中设置命令路径。权限或账户停用导致不可读时只报告不可读，不自动启用账户。本公开版尚未验收新的Google端到端配置。

## 素材与备份

Web只读挂载 `/data`；下载Worker才可写入。`worker/` 是复用源码，不默认启动，媒体队列由管理员按实际来源接入。需要Python、PostgreSQL客户端、FFmpeg和file。原文件以哈希命名保留；派生视频另存。

NAS应由宿主机安全挂载，并验证写入和回读。不要在仓库写服务器、共享盘、用户名或密码。备份Worker通过 `DATABASE_URL`、`MEDIA_ROOT`、`NAS_ROOT` 和 `BACKUP_STATE` 配置。Web不需要NAS写权限。每份备份的校验不等于已验证恢复；恢复到独立临时库验收后才能标记恢复成功。

## 每日规则复盘（需人工安装与验收）

1. 已处于真实模式，自己的精确账户/系列/组/广告ID已有初始学习记录，且四层关联一致。
2. 将 `config/daily-review.example.json` 中的虚构ID、日期和预算替换成自己的配置。该文件没有任何真实监控对象。
3. 核实 `REVIEW_DB_HOST` 与数据库主机一致；不要把连接守卫改成任意库可写。
4. 建立可由UID1000写入的受控证据outbox。先运行 `docker compose --env-file .env.local --profile live-review run --rm daily-review node scripts/daily-review.mjs --trial`。默认命名卷首次权限可能需要管理员初始化；勿盲目改现有素材盘权限。
5. 回读对应广告的学习记录、证据哈希、数据库与NAS各自状态；再次试运行，必须得到同一记录而非重复追加。失败时不要开启调度。
6. 验收后由自己的Linux调度器在每天09:00 America/Los_Angeles运行daily-review服务，10/12/15点重试。不要同时保留另一台电脑的重复任务。公开版不自动安装宿主机服务。

当前规则固定美元和太平洋时区；测试结束只继续复盘，不重启。规则不是AI模型。接入模型、自动告警或扩大监控范围需要另行设计和验证。

## 安全与未完成项

当前是单人会话模型、未通过独立安全审计，暂不支持多租户隔离。远程运行需要自己的TLS与访问控制。不要公开管理端、数据库、日志或文件目录。功能不等于生产加固完成，见 SECURITY.md。
